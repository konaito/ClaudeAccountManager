# Claude Account Manager (cam)

cam は、1台の Mac で Claude Code をアカウントごとのコマンドで起動するための bash スクリプトです。`ceo` と打つと ceo@fybe.jp で、`claude` と打つと既定のアカウントで起動し、2つは別のターミナルで同時に動かせます。

仕組みは公式ドキュメントの「Log in with multiple accounts」にある `CLAUDE_CONFIG_DIR` です。アカウントの自動切り替えはしません。
https://code.claude.com/docs/en/authentication

## 何が分かれて何が共通か

アカウントごとに分かれるもの:

- ログイン（macOS の Keychain の項目は `CLAUDE_CONFIG_DIR` ごとに別になる）
- `.claude.json`（ログイン中のアカウント情報を含む）と、その控えの `backups`
- 組織ごとの値（`policy-limits.json`、`remote-settings.json`）
- MCP の認証状態（`mcp-needs-auth-cache.json`）
- Claude Code が設定ディレクトリに作る lock（`*.lock` と `*.lock.*`。`.oauth_refresh.lock` とその `.owner`、`mcp-refresh-*.lock`、`computer-use.lock`、`server.lock` など）

lock は Claude Code が作っては消すので、リンクで共有できません。`.oauth_refresh.lock` がリンクだと、Claude Code はトークン更新の lock を外せず（`ENOTDIR`）、約8時間でアクセストークンが切れて `/login` を求めます。`cam sync` は、前の版の cam がこれらの名前で張ったリンク（`~/.claude` を指すもの）を消します。実体のファイルやフォルダは消しません。

それ以外の `~/.claude` の中身は、全部シンボリックリンクで共通にします。設定、スキル、会話履歴に加えて、`sessions` も共通です。そのため、どのアカウントで起動したセッションからも、`ListAgents` と `SendMessage` でほかのセッションが見えます。

Claude Code が起動後に作るフォルダ（`sessions`、`session-env`、`teams`、`tasks` など）は、`~/.claude` に先に作ってからリンクを張ります。プロファイルにすでに実体があるときは、中身を `~/.claude` に移してからリンクにします。`~/.claude` に同じ名前のものがあれば、捨てずにプロファイルの `.cam-replaced/<時刻>/` に残します。

ユーザーの MCP サーバーの正本は `~/.claude.json` の `mcpServers` です。cam は起動のたびに、次の順で同期します。

1. どれかのプロファイルの中で足された MCP（`claude mcp add --scope user` はプロファイルの `.claude.json` に書きます）を、`~/.claude.json` に取り込みます。同じ名前で中身が違うときは `~/.claude.json` を残します
2. `~/.claude.json` の `mcpServers` を、ログイン済みの全プロファイルへ写します。起動するプロファイルだけでなく、ほかのプロファイルにも写します

MCP を消すときは `~/.claude.json` から消します（`env -u CLAUDE_CONFIG_DIR claude mcp remove -s user <名前>`）。次の同期で全プロファイルから消えます。プロファイルの中だけで消しても、`~/.claude.json` から戻ってきます。前の同期で配った名前は `~/.cam/mcp-distributed.json` に控えます。プロファイルにだけある名前は、控えにあれば「消されたもの」として捨て、控えに無ければ「足されたもの」として取り込みます。

フォルダを開いたときの「Yes, I trust this folder」の記録は `.claude.json` に入るので、そのままではアカウントごとに聞かれます。cam は起動のたびに、`~/.claude.json` と全プロファイルの `.claude.json` から信頼済みのフォルダを集め、ログイン済みの全プロファイルの `.claude.json` に写します。どれか1つのアカウントで信頼したフォルダは、次に cam でどれかのアカウントを起動したあと、どのアカウントでも聞かれません。この同期では、集めた信頼済みのフォルダを `--default` で作ったコマンド（`~/.claude`）の `~/.claude.json` には書き込みません。起動したフォルダだけは、下の `cam trust` が `~/.claude.json` にも書きます。

起動用コマンドは、claude を起動する前に `cam trust` を実行し、起動したフォルダを信頼済みにします。初めて開く git リポジトリでも、確認画面は出ません。書く先は `~/.claude.json` とログイン済みの全プロファイルの `.claude.json` で、`--default` のコマンドでも同じです。

- Claude Code（2.1.332 で確認）は、起動したフォルダの実体のパスから上へたどって信頼済みのフォルダを探します。git リポジトリの中では、`.git`（フォルダかファイル）があるいちばん近いフォルダでたどるのを止めます。そのため `~/Documents` を信頼済みにしても、その下の git リポジトリには効きません
- `cam trust` は、git リポジトリの中ならそのいちばん上を、外なら起動したフォルダを書きます。worktree とサブモジュールでは、それぞれのフォルダをいちばん上とみなします
- Claude Code がたどる範囲のどれかがすでに信頼済みのファイルには、何も書きません
- ホームフォルダは書きません。Claude Code もホームの信頼は記録しないためです
- 読めないファイルには書きません。書くときは一時ファイルに書いてから置き換えます

起動用コマンドは `cam sync` を呼ぶので、どれかのプロファイルを起動すると、前の版の cam が作った起動用コマンドを今の形に作り直します。作り直すのは、2行目の説明が cam の形のものだけです。

動いているセッションは、起動したときに読んだ設定のままです。同期した内容は、そのアカウントを次に起動したときに使われます。同時に起動した cam が `~/.claude.json` を書き合わないよう、同期は `~/.cam/.sync.lock` で1つずつにします。1分より古いロックは、止まった cam の残りとして消します。

`cam sync` は、大元と全プロファイルの `.claude.json` を jq で1回だけ読み、写す必要があるファイルだけを書きます。何も変わっていなければ、どのファイルも書きません。読めないファイルがあるときは、1つずつ読んで同期します。

## 置き場所

- このリポジトリ: `cam` 本体
- `~/.cam/bin/`: `cam` 本体へのリンクと、`cam add` で作った起動用コマンド（PATH に入れる）
- `~/.cam/profiles/<名前>/`: 各アカウントの `CLAUDE_CONFIG_DIR`。ログイン情報が入るので git には入れない

## 入れ方

```bash
mkdir -p ~/.cam/bin
ln -s ~/Documents/cam/cam ~/.cam/bin/cam
echo 'export PATH="$HOME/.cam/bin:$PATH"' >> ~/.zshrc
```

## 使い方

```bash
cam add ceo            # ~/.cam/profiles/ceo と ceo コマンドを作り、ログインして起動する
cam add cto --no-login # 作るだけで、ログインと起動はしない
cam add cto            # 既にあるコマンドなら、そのアカウントでログインし直して起動する
ceo                    # 2回目からはコマンドだけで起動する
cam add coo --default  # ~/.claude のログインで起動する coo コマンドを作る
cam list               # コマンドとログイン中のアカウント
cam auto               # 7日枠の保護枠を残せるコマンドから選んで起動する
cam usage              # 各コマンドの使用率と、cam auto が選ぶコマンド（--json でメニューバー用）
cam refresh            # 期限切れのトークンを Claude Code 本体に更新させる（名前を付けるとそのコマンドだけ）
cam sync ceo           # 共有リンクと MCP を同期する（起動時にも自動で行う）
cam trust              # 今のフォルダを全アカウントで信頼済みにする（起動時にも自動で行う）
cam remove ceo         # コマンドとプロファイルを消す
```

既存のコマンドと同じ名前（`ls` など）は作れません。

`cam add` は `claude auth login` でブラウザのログインを開き、通ったらそのまま Claude Code を起動します。端末から実行していないときはログインせず、手順だけを表示します。

## cam auto の選び方

`cam auto` は各コマンドの使用率を調べ、7日枠（Weekly）を使い切るコマンドを出さないように選んで起動します。引数はそのまま `claude` に渡します。5時間枠はすぐ戻りますが、7日枠を使い切ったコマンドは長いあいだ使えません。そのため、7日枠に一定の残り（保護枠）を残せるコマンドを優先します。

使用率は全コマンドぶんを同時に調べます。表示はせず、選んだコマンドをそのまま起動します。保護枠を使うとき、使えるコマンドが無いとき、使用率を判定できないときだけ、そのことを表示します。

選び方は次のとおりです。H は5時間枠の残り、W は7日枠の残りで、どちらも `1 − 使用率` です。

1. 保護枠 R を `0.15 × min(1, 7日枠のリセットまでの時間 / 24時間)` で決めます。リセットまで24時間以上あれば15%を残し、リセットが近づくほど小さくします。7日枠のリセット時刻が分からないときは15%にします
2. 次の作業で使う量を ΔH・ΔW として、`H ≥ ΔH` かつ `W − ΔW ≥ R` のコマンドを通常候補にします。通常候補の中から、`3 × ΔW / (W − R) + ΔH / H` がいちばん小さいコマンドを選びます。7日枠の余裕が少ないコマンドほど値が大きくなります
3. 通常候補が無いときは、両方の枠が100%未満のコマンドから保護枠を使って選びます。`W − R` が0以下になりうるので、`3 × ΔW / W + ΔH / H` で比べます。その前に、次の作業ぶんが残っているコマンドを優先し、次に、使っても新しく保護枠を割らないコマンドを優先します。保護枠を残しているコマンドの数を減らさないためです
4. 両方の枠のどちらかが100%のコマンドしか無いときは起動せず、いちばん早く戻るコマンドとその時刻を表示します

ΔH と ΔW は仮置きの値で、全コマンド共通の `ΔH = 0.10`（5時間枠の10%）、`ΔW = 0.02`（7日枠の2%）です。実際の消費量はまだ測っていません。0.15、24時間、3 と合わせて `cam` の冒頭の定数にまとめてあります。

- 使用率が取れないコマンドは、前回取れた値（控え）で比べます。ただし5時間より前に取った控えは使わず、使用率の分からないコマンドとして扱います。5時間枠がまるごと入れ替わり、控えの値と今の値が大きく違うことがあるためです
- 使用率が取れず控えも無いコマンドは候補から外します。使えるコマンドが無く、使用率の分からないコマンドが1つでもあるときは、使用率の分からないコマンドから選んで起動し、各コマンドが取れなかった理由を表示します。上限と分かっているコマンドは選びません。5時間より前の控えがあり、その5時間枠のリセット時刻を過ぎていて、7日枠が100%でないコマンドを先に選びます。その中では `--default` のコマンド、無ければ `cam list` の順で先のコマンドを選びます
- スコアが同じときは、`cam list` の順で先のコマンドを選びます

使用率は、Claude Code が Keychain に保存したログインのトークンで `https://api.anthropic.com/api/oauth/usage` を呼んで取ります。この API は公開されていないので、仕様が変わると `cam auto` だけ動かなくなります。トークンの期限が切れているコマンドは、一度そのコマンドを起動するか、`cam refresh <名前>` を実行すると Claude Code が更新します。期限切れのトークンでも API は 429 を返すことがあるので、Keychain の expiresAt で期限を確かめ、切れていれば API を呼ばずに「トークンの期限切れ」と出します。このときも控えがあれば控えの値を使い、期限切れの理由を一緒に出します。期限切れのコマンドも、起動すれば Claude Code がトークンを更新するので、5時間以内の控えなら `cam auto` の候補にします。Keychain には同じ項目名で acct の違う項目ができることがあるので、先に acct がログインユーザー名の項目を読み、トークンが無ければ acct を指定せずに読みます。

この API は、低い頻度で呼んでも 429（Rate limited）を返すことがあります。そのため、取れた値はコマンドごとに `~/.cam/usage-cache/<名前>` に控えておき、取れないときは控えを使います。`cam usage` では、控えの値に「◯時◯分時点の値」と付け、5時間より前の控えには「cam auto では使わない」と付けます。控えのリセット時刻を過ぎた枠は、使用率を 0% として扱います。

## cam refresh

`cam refresh` は、トークンの期限が切れたコマンドで Claude Code を1回走らせ、Claude Code 本体にトークンを更新させます。cam は refresh のエンドポイントを呼ばず、Keychain にも書きません。

```bash
cam refresh            # 期限切れか期限5分以内のコマンドを全部、1つずつ順に更新する
cam refresh shared     # shared だけを更新する
```

走らせるのは次のコマンドです。作業フォルダは空の一時フォルダにし、標準入力は渡しません。

```bash
env -u <消す変数...> CLAUDE_CONFIG_DIR=<プロファイル> claude -p /usage --output-format json --tools "" \
  --strict-mcp-config --setting-sources "" --no-session-persistence --debug-file ~/.cam/refresh-log/<名前>/debug.log
```

- `--default` のコマンドは、`CLAUDE_CONFIG_DIR` を付けずに走らせます。ロックと動いている claude は `~/.claude` で見ます
- 消す変数は、`ANTHROPIC_` と `CLAUDE_CODE_` と `CLAUDE_PLUGIN_` で始まる変数、`CLAUDECODE`、`CLAUDE_PID`、`CLAUDE_EFFORT`、`CLAUDE_CONFIG_DIR`、`CLAUDE_ENV_FILE` です。Claude Code のセッションの中から呼んだときに、セッションのトークンや設定を引き継がないためです
- 外から打ち切りません。打ち切ると、更新を送ったのに保存しないまま終わることがあるためです。走っている途中に Ctrl-C で止めないでください

走らせると次のことが起きます。2026-11-28 に Claude Code 2.1.332 の shared で1回試した結果です（#23）。版や機能フラグが変わると変わることがあります。

- 推論は呼びません。`/usage` は `-p` ではモデルに聞かずに答えるコマンドで、出力は `num_turns: 0`、`total_cost_usd: 0` でした。5時間の枠は、この実行では始まっていないと読めました（1回の観察からの読みです）
- アクセストークンは更新した時刻の8時間後まで延びました
- refresh token はサーバーで差し替わりました。前の refresh token は使えなくなったと考えてください。`refreshTokenExpiresAt` は延びませんでした
- 1回あたり数秒かかります。初めて走らせるプロファイルでは、プラグインのマーケットプレイスの取得で長くなることがあります

次のときは走らせず、飛ばした理由を出します。

- 期限まで5分より先のとき。本体は期限の5分前まで更新しないので、走らせても延びません
- トークンが無いとき、期限（`expiresAt`）が分からないとき
- `refreshTokenExpiresAt` を過ぎているか分からないとき。そのコマンドを起動して `/login` してください
- 同じコマンドを10分以内に試したとき。試した時刻は `~/.cam/refresh-at/<名前>` に残します。失敗も数えます
- そのコマンドの claude が動いているとき。`ps eww` で、実行ファイルの名前が `claude` で `CLAUDE_CONFIG_DIR` がそのプロファイルのプロセスを探します。動いている claude は自分でトークンを更新します
- ロック（`<プロファイル>/.oauth_refresh.lock` か `<プロファイル>.lock`）があるとき

成否は、走らせた後に Keychain の `expiresAt` を読み直し、延びたかで決めます。終了コードは使いません。結果はコマンドごとに1行ずつ出し、1つでも更新されなかったら終了コード 1 で終わります。最後に走らせたときの debug ログと出力は `~/.cam/refresh-log/<名前>/` に残します。資格情報が空になったときは、そのコマンドを起動して `/login` してください。

メニューバーからは呼びません。`cam auto` からは、次の節の条件のときだけ呼びます。

### cam auto での更新

`cam auto` は、使用率を集めて選んだ結果が「通常候補が無い」ときだけ、トークンの期限が切れたコマンドを `cam refresh` と同じ手順で更新してから選び直します（#29）。

更新を走らせるのは、次の2つがそろったときです。

- 選んだ結果が、保護枠を使う候補（`cam usage --json` の `choice` が `fallback`）か、判定できない（`unknown`）
- 期限切れのコマンドのうち、選ぶときに値を使えないものがある。値を使えないのは、使用率が取れず控えも無いときと、控えが5時間より前のときです

次のときは走らせません。

- 通常候補がある（`normal`）とき。期限切れのコマンドを更新しても、すでに保護枠を残せるコマンドを選べるためです
- 全部が上限と分かっている（`none`）とき。このときは値の分からないコマンドが無いので、期限切れで対象になるコマンドもありません
- 期限切れでも5時間以内の控えがあるとき。`cam auto` は控えの値で選ぶので、更新しても選ぶ結果は変わりません
- `cam usage` と `cam usage --json`。メニューバーが5分ごとに呼ぶためです

対象のコマンドは、コマンド順に1つずつ更新します。10分に1回まで、動いている claude かロックがあれば飛ばす、外から打ち切らない、成否は `expiresAt` で見る、という決まりは `cam refresh` と同じです。更新している間は、コマンドごとに次の1行を標準エラーに出します。

```
cam: shared のトークンが期限切れなので更新します（cam refresh shared、1つ数秒）… 更新した（期限 11/28 20:00 まで）
```

更新の後でトークンが期限内になったコマンドだけ、使用率を取り直して選び直します。飛ばしたときと更新されなかったときも `cam auto` は止めず、更新しなかったときと同じ選び方で起動します。

更新を走らせる場面では、`cam auto` の起動が1コマンドあたり数秒遅くなります。#23 の shared の実測では約7秒でした。期限切れのコマンドが3つあれば、約20秒待つことになります。`cam auto` を2つほぼ同時に走らせると、同じコマンドの更新が2回走ることがあります。試した時刻（`~/.cam/refresh-at/<名前>`）は claude を走らせる前に書くので、数秒ずれていれば後のほうは飛ばします。cam はこのためのロックを作りません。

## メニューバー

`menubar/` の CamBar は、`cam usage --json` の結果をメニューバーに出すアプリです。メニューバーには `cam auto` が選ぶコマンドとその5時間枠の使用率を出し、開くと各コマンドの5時間枠と週次の使用率、リセット時刻を出し、`cam auto` が選ぶコマンドには `*` を付けます。控えの値を出しているコマンドには、名前の下に「◯時◯分時点の値」と出します。使用率が出せないコマンドには、429・トークン切れなどの理由を出します。アカウントの切り替えはしません。

```bash
menubar/install.sh   # ビルドして ~/Applications/CamBar.app に置き、ログイン時に起動するようにする
```

使用率は5分ごとに取り直します。ログイン時の起動には `~/Library/LaunchAgents/jp.fybe.cam.menubar.plist` を使います。

## 注意

- API キーを使わない Claude Console のサインインは、保存先が `CLAUDE_CONFIG_DIR` の外にあるので、アカウントごとに分けられません（公式ドキュメントの記述）
- リモートの MCP サーバーは、プロファイルごとにもう一度認証が要るかもしれません（未確認）
- `cam remove` は Keychain の項目を消しません
- MCP と信頼済みフォルダの同期の回帰テストは `tests/mcp_sync_test.sh` です。HOME を一時ディレクトリに替えて動かします
- 起動時に信頼済みにする試験は `tests/trust_on_launch_test.sh` です。HOME を一時ディレクトリに替え、偽の claude を PATH の先頭に置いて動かします
- `cam refresh` の試験は `tests/refresh_test.sh` です。HOME を一時ディレクトリに替え、Keychain の代わりのファイルの expiresAt を延ばす偽の claude を PATH の先頭に置いて動かします
- `cam auto` が期限切れのコマンドを更新してから選ぶ試験は `tests/auto_refresh_test.sh` です。`tests/refresh_test.sh` と同じ偽の claude に加え、API の応答をコマンドごとのファイル（`CAM_TEST_API` にディレクトリを渡す）で差し替えます
- 変わっていない `cam sync` が何も書かないことと、入力が変わったら同期し直すことの試験は `tests/sync_unchanged_test.sh` です
- 起動用コマンドの前段（`cam trust` と `cam sync`）の時間は、`bench/launch_prefix.sh [回数] [比べる版]` で測ります。本物の設定を一時 HOME に写して、2つの版を交互に走らせます
